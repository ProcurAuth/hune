This document uses ASD-STE100 Simplified Technical English.

This document is not normative. It gives the state of the code at version 0.1.1 against the specification 0.1. The specification stays the reference. Where the code differs from a paragraph, the table "Differences from the specification" names the paragraph. Section 18 of the specification (08-roadmap-open-items.md) gives the milestones and their exit criteria.

Checks on real data

The milestone M0 and the parity spike of 18.3a are not done. The verification V1 to V5 of 15.14 is not done either. These checks need a copy of a real Grafana installation and runs on its ClickHouse server.

All tests of this repository use synthetic data. Thus the document format and the expander are not frozen against real dashboards. The measures of Grafana 12.4.2 in 19.20a to 19.20n come from temporary dashboards on a local instance.

Open points

  • The security choices of the PostgreSQL source (19.32) and of the MongoDB source (19.33) are open questions. The code follows the default of each choice.
  • The advisory RUSTSEC-2026-0387 of crypto-bigint 0.5.5 stays in the list ignore of deny.toml until procurauth-core moves to p256 0.14.
  • The origin of web/icons.svg, the commit pins of the workflow actions, and the toolchain of the fuzz job need a check.
  • WebAssembly in the page is not done.

How to build and test

Use these commands from the root of the repository. The toolchain file selects Rust 1.99.1.

  1. Run cargo build --workspace --locked.
  2. Run cargo test --workspace --locked.
  3. Run cargo clippy --workspace --all-targets --locked -- -D warnings.
  4. Run cargo fmt --all -- --check.
  5. Run node --test tests/frontend/*.test.mjs.
  6. Run tests/ci/policy.sh --local.
  7. Run python3 -I tools/ste_lint.py docs/*.md README.md CHANGELOG.md.

The workflows in .github/workflows run the CI and the release on GitHub. They are optional. An operator can run every job and the release with tests/ci/all.sh and tests/ci/release.sh, with no GitHub Actions. The script tests/ci/all.sh runs every job of the merge gate in order and stops at the first failure (16.17). The option --list prints the jobs.

These scripts need Docker. Each one starts local containers on 127.0.0.1 and removes them at the end.

How to run Hune

  1. Write a configuration file. Start from the output of hune print-reference --format hcl --profile local.
  2. Run hune check-config -c <file>. Correct each error that it gives.
  3. Run hune serve -c <file>.
  4. Open the address of server.listen in a browser.

Differences from the specification

ParagraphDifferenceWhy
4.24The regex subset refuses three more forms than the table.The Rust engine and the browser engine must read a pattern in the same way.
13.11, 13.17The key order of access.pdp follows 13.17.The reference file of 13.17 sets the order.
7.11An empty insertion also gets the token check.The token check applies to each insertion, with no exception.
7.16, 8.3ClickHouse gives decimals without trailing zeros with the settings of 8.3.ClickHouse formats the decimal, and Hune keeps the text that it receives.
8.7The TCP keepalive idle time is the default of the system.The system sets the idle time.
9.3, 9.24The build accepts the file web/js/vendor/chdash/LICENSE.The licence file of the copied chart engine is one of the vendored files.
16.10The browser tests use Chrome through the DevTools protocol, not Playwright.The runner needs no download and has no npm dependency.
16.10a, 16.17The front-end tests run with a file glob.node --test on a directory fails on Node 22.
19.20The gaps of the copied chart engine stay.An edit of the engine is made only for a gap that a real panel uses (19.20).

The specification states the look of the front end and the document format 3. The text of 4.42 stays as the code has it.
